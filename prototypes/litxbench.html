Literature Extraction Agent

Before Antimatter can predict a new alloy, it needs training data — and decades of it already exists, locked in published papers as prose and tables. This console turns a paper into structured, auditable measurements.

Why this screen exists This is the only console grounded in a peer-reviewed artifact rather than a marketing page: LitXBench (Chong & Colindres, arXiv:2604.07649) introduces a benchmark and a 1,426-measurement dataset (LitXAlloy) from 19 alloy papers, and finds frontier LLMs beat existing extraction pipelines by up to 0.37 F1 — because those pipelines link measurements to compositions but not to the processing steps that actually define a material. Everything about the interaction design here is invented; the dataset facts and finding are direct from the paper.

Goal

Turn decades of published alloy research into structured training data for Antimatter, instead of starting every new material family from zero lab measurements.

Problem

Off-the-shelf extraction pipelines silently produce wrong data — they'll correctly pull "310 MPa yield strength" but attach it to the alloy's composition alone, dropping the fact that it only holds after a specific heat treatment. The error doesn't look like an error; it looks like a clean row in a spreadsheet.

One measurement, pulled out of prose and a table footnote, as a structured record.

Measurement( composition="Al-0.3Sc-0.15Zr", property="yield_strength", value=310, unit="MPa", processing=[ "solution treat 640C/1h", "quench", "age 325C/18h" ], source_span="Table 3, row 4; Sec. 2.2 para 3" )
Why Python objects, not CSV/JSON LitXBench stores entries as Python objects specifically "to improve auditability and enable programmatic data validation" — you can write a unit test against a measurement record and catch a malformed extraction before it ever reaches a training set, which a loose CSV row can't give you.

The paper's core finding, made concrete: the same sentence, extracted two ways.

Legacy multi-turn pipeline

310 MPa→Al-0.3Sc-0.15Zr
age 325°C/18h

Correctly finds the number and the alloy. Drops the aging step — so the record silently implies 310 MPa is an as-cast property. It isn't.

Frontier LLM (Gemini 3.1 Pro Preview)

310 MPa→Al-0.3Sc-0.15Zr→age 325°C/18h

Links the measurement to composition and the processing step that produced it — the paper's stated reason frontier models pull ahead on this task.

Why this feeds Antimatter

Every correctly-linked measurement here is a training example Antimatter's prediction engine can use without ever running a physical experiment. Getting the extraction wrong doesn't just lose data — per the paper's own framing, it actively teaches the model a false correlation between composition and property, silently, at scale.

The story this screen is solving

Realistic scenario

Omar's team wants to expand Antimatter into a new alloy family it has no lab data for yet. Running physical experiments to bootstrap that family from scratch would take months on the Autonomous Lab (console 02). Instead, Omar points the extraction agent at the existing published literature for that family overnight. The catch, and the entire reason LitXBench exists as a research artifact: a naive extraction pipeline would hand Antimatter thousands of confidently-wrong training rows, each one looking exactly as valid as a correct one — a mistake that wouldn't surface until Antimatter started recommending compositions that don't behave the way the (mislabeled) literature said they would.
